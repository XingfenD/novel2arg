# 基线测试常见失误（观察所得；逐条避免）

在真实项目上运行本 skill 时观察到的陷阱，按所属工作流步骤分组。
每个步骤文件引用其小节；当某步骤引用本文件时，编排者把它放进该
子 agent 的派发 prompt。交回该步骤产物前先检查对应小节。小节编号
沿用工作流步骤；规则编号 `(Rn)` 引用 `references/guardrails_zh.md` 的权威表。

## Step 1 — 拆解

| 失误 | 正确做法 |
|---|---|
| 只按故事时间顺序 | 反转点按玩家发现顺序重排；中心反转页在一页内释放多个侧钩 |

## Step 2 — 容器与模块选择

| 失误 | 正确做法 |
|---|---|
| 把账号 / 登录系统硬塞进一个没有系统类虚构的故事 | 触达跟随容器：公开网站靠搜索与密码门区分层次，系统类虚构靠账号（`workflow/02-container_zh.md`） |
| 为"保险起见"打开每个可选模块，或没问用户就替 TA 选了换肤冲击 | 模块在步骤 2 与用户一起选择并记录进 `docs/system-profile.md`；构建出的站点与选择严格一致 |

## Step 3 — 撰写 GDD

| 失误 | 正确做法 |
|---|---|
| 谜题与角色脱节（抽象机制、随机密码） | 密码 = 人物推断；找到密码 = 理解一个角色（R3） |
| 靠形容词和跳吓文案制造恐怖 | 恐怖靠官僚台账、重复（一句话抄 21 遍）、缺席（无人回复的帖子、`[已删除]`） |
| 结局是一张成绩单 | 结局复用玩家刚读过的文件；选择 M10 时给道德选择 + 第四面墙收尾 |
| 选择 M7 时没有进度反馈 | 每页页脚 `NN/total`；深层页使用 `ex/total` 之类的异常编号 |
| （网站形态）一张平铺关键词索引横跨两个区域；（系统形态）把访问控制维护在关键词 JSON 里 | 网站形态：按受众分索引（R8）。系统形态：单一索引，由页面上的账号矩阵决定命中打开什么——访问控制永不放在 JSON 里（R10；`references/structure/form-system_zh.md` §1） |
| （系统形态）同事的登录名印在公开页上（名册里的 `账号：chen.gd`） | 只有初始账号可以印出；其他账号一律从文字线索推断（R10；`references/structure/form-system_zh.md` §1） |
| GDD 自相矛盾——一个页面有两种叫法（页面地图 vs. 导航 vs. 它自己的标题），或某值一行禁止、另一行却要求出现在同一页 | 在用户检查点之前跑步骤 3 自洽扫描；GDD 实体登记表是每个页面复制的唯一事实来源 |
| 示例值违反它所演示的规则（样例 `wang00□□` 对上一套"拼音首字母"规则，或形状错误） | 每个示例都满足声明的推导规则，并与真实值的长度 / 分隔符 / 掩码一致 |
| 同一凭据的两个部件同置一页（工号 + 年份同页 → 零跳通关） | 把部件拆到不同页面，让推导本身成为谜题（R3；GDD 谜题分配表） |

## Step 4 — 触达性

| 失误 | 正确做法 |
|---|---|
| 为串联线索而线索植入链接 | 线索投递走站点自身的信息架构：导航栏、索引页与列表页、站点地图、搜索（R7） |
| 浅层页在"相关文件 / 档案 / 页面"名义下链接深层页 | 仅同区域引用；深度由触达模块跨越（R7；`references/structure/form-system_zh.md` §1） |
| 数值权限阶梯，或一个能打开一切的 admin 账号 | 按账号授权：页面只对它所命名的账号开放（`data-access`）；没有权限继承（R10；`references/structure/form-system_zh.md` §1） |
| 概括情节的结果标题（"…完整版"、"四名家长信息"） | 档案机构会印出的目录条目：发布主体 + 文件类型 + 编号/日期（R9） |
| 打不开的条目让人无从理解它为何被锁 | 它落到自己的门或一条朴素的未开放提示；绝不打开文件（R8） |
| 没人能到达的孤儿页 | 步骤 4 在脚手架前审计图；步骤 8 再走一遍 |

## Step 5 — 谜题审计

| 失误 | 正确做法 |
|---|---|
| 答案出现在 `placeholder` 或帮助文本里 | 只命名字段；反馈由含蓄的失败提示承担（R4） |
| 因为门已经写好了就留着 | 步骤 5 的必要性之问；辩解留空的即为删除 |
| 为了 `check-solvable` 变绿而把派生账号印到公开页 | 它只匹配逐字字符串，派生凭据因此读作 STUCK；用 `check-credentials.mjs`（部件 + 规则 + 零明文）证明它，绝不打印——静态站点没有服务端鉴权，客户端遮蔽不是隐私 |

## Step 6 — 脚手架

| 失误 | 正确做法 |
|---|---|
| 搭一个 SPA 冒险引擎（canvas 场景、通用谜题框架） | 多页假系统；每个页面是可独立打开的"文件"（R1） |
| 模块漂移：框架带上了 profile 未选的机器，或漏掉选中的 | 严格构建选中的模块——没有未用皮肤、搜索表、门组件或账号家具（`workflow/06-scaffold_zh.md`） |
| 关键词以明文 JSON 存储 | 构建脚本把它们哈希成表，杜绝"读源码通关"（R3） |
| 为了迁就改名项目而重写检查器 | 共享的 `tools/config.mjs` 吸收改名后的目录、层名、标记与搜索挂载点；`references/structure/tooling_zh.md` §2 列出旋钮，§3 列出静态检查替代不了的步骤 |
| （6a）prompt 携带小说、GDD 或其他承载情节的产物 | 6a 只读 `docs/system-profile.md` 加基础设施类参考；把情节挡在其上下文之外正是这次拆分的目的 |
| （6a）为了填满空正文，把情节文案写进基础页 | 基础页承载系统自己的词；此阶段正文为空或占位才是正确的 |
| （6b/7）重建或改样式 6a 产出的框架 | 外壳、皮肤、组件与工具在 6a 定稿；6b 只加骨架，步骤 7 只填内容 |

## Step 7 — 实现

| 失误 | 正确做法 |
|---|---|
| 公开页陈述情节（"主厨——也是 2019 年消失的那个人"） | 公开页发布该组织发布的内容；情节由玩家从暗层拼出（R5） |
| 公告写成游戏提示 | 真实文件格式：发布主体、编号、日期、受文者、正文、印章、分发范围（R6） |
| 引导文案用隐喻与拟人装饰 | 朴素的陈述句（R11） |
| 站点文案出现对偶句式（是…不是… / 是…而是…） | 每句一个肯定分句（R11；`references/design-playbook_zh.md` §4.14） |
| 编排者自己动手写页面 | 每个工作流步骤一个子 agent；编排者只派发与审阅 |
| 声明过的图片 / 印章 / 扫描件 / 照片从未落地（没写 `<img>`，检查器无从抱怨） | 步骤 7 的 phase 4 认领 GDD 资产清单；步骤 8 把每个声明资产对到文件 + 引用 |
| 为给检查器"一个表单 = 一个身份"把一个登录拆成两个表单 | 一个框 + `data-grants`（账号→身份映射）；两个表单会在标题里泄露设计意图，读起来像游戏 UI（`references/structure/form-system_zh.md` §2） |
| 访问状态放在按标签页的 `sessionStorage` 里，而结果 `target="_blank"` 打开 | 会话 Cookie（跨标签页）；否则新标签页读作已登出（`references/structure/components_zh.md` §2–§3） |
| 为满足静态检查器而明文打印凭据 | 零明文：`check-credentials.mjs` 断言没有任何账号完整出现；静态站点上客户端遮蔽不是隐私 |

## Step 8 — 自检

| 失误 | 正确做法 |
|---|---|
| 只在表单 UI 里做泄答扫描 | 页面**外框**也要扫——`<title>`、顶栏、页脚。答案印在页头与印在 `placeholder` 里是同一种缺陷（R4） |
| 因为 `check-solvable` 是绿的就不测跨标签页解锁 | 它把身份建模为一个全局集合，看不到按标签页隔离；跑人工新标签页测试（登录 → 打开 `target="_blank"` 结果 → 受保护文件必须在新标签页中解锁） |
| 资产清单未对账 | 每个 GDD 声明的资产都存在于 `assets/` 下且被至少 1 个页面引用；没写出来的 `<img>` 没有 `src` 供 check-links 解析 |
| 共享实体在页面间漂移 | 拿姓名 / 编号 / 账号 / 页面标题 / 日期与 GDD 实体登记表对账；名册漏掉值班表上的人，或页面挂着两个标题，在此失败 |
| 没跑可解性检查就发布 | 脚手架时把 `assets/tools/check-solvable.mjs` 复制进来。它证明内容修改后每个门仍可解、每个页面仍可触达，并在修复泄答删掉线索时变红。派生凭据另加 `check-credentials.mjs` + `check-reachability.mjs` |
