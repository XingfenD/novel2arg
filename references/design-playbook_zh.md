# 设计模块 —— 目录与组装（规定性）

> 步骤 2 的菜单。选择小说真正需要的模块，然后组装进
> `docs/system-profile.md`（`workflow/02-container_zh.md`）。默认：容器的原生触达模型加
> 入口页；此后每个模块都必须在虚构中挣得位置。规则编号 `(Rn)` 引用
> `references/guardrails_zh.md`；章节引用采用 `§N.M` 形式 = 第 N 节第 M 项。组件实现：
> `references/structure/components_zh.md`。

## 1. 核心循环（始终开启）

- **总公式**：入口仪式页 → 伪装的容器 → 核心循环（读 → 提取 → 解锁）→ 表层裂缝 →
  分阶段升级进入暗层 → 中心反转页 → 终局 → 结局。
- **五阶段升级**：（1）以服务之名 →（2）系统性之恶 →（3）人的灰色 →（4）玩家自己的
  罪责 →（5）循环指向玩家。
- **按发现排序**：反转点遵循玩家发现顺序，而非故事时间顺序（`workflow/01-deconstruct_zh.md`）；
  动机文件最后出现，把"击败怪物"重构成"理解怪物"。
- **页面本身就是角色**（最高阶装置）：站点由某个角色在虚构内搭建（凶手的官网 /
  失踪者留下的最后任务）——浏览本身就是情节。

## 3. 谜题类型（成组挑选 5–10 个）

**铁律：密码即人物推断。** 每个凭据都是某个角色的生活痕迹（由生肖年推出的出生年、
孩子的生日、首字母、车牌、工号）。找密码的过程就是理解一个角色的过程。

| 类型 | 机制 |
|---|---|
| A 关键词搜索门 | 字面词 → 哈希查找 → 隐藏页；容忍同义 / 别名；一个关键词可返回多条结果。访客打不开的命中落到它的门或未开放提示（M1/M2），绝不落到文件 |
| B 跨页凭据投递 | **三要素：A 页账号、B 页密码线索、C 页密码门**——最小谜题单元。凭据可以是*派生*的（账号 = 拼音首字母 + 车牌年份，密码 = 入职年份），由部件拼装而非整串印出；用 `tools/check-credentials.mjs` 证明它，绝不打印它（`references/structure/components_zh.md` §3） |
| C 密码藏在 URL | 文件名 / 路径就是凭据（`passwordisXXX.html`）；地址栏成为叙事道具；慎用——它会破坏揭示 |
| D 经典密码学 | 波利比奥斯方阵、摩斯码（1:3 的音频点划）、书本密码（页-行）；在页面上呈现，客户端校验 |
| E 感官谜题 | 立体声声场分离（入口页声明耳机要求）、点击计数、手电筒遮罩（radial-gradient + 光标追踪） |
| F 视觉隐藏 | 选中才显的黑底黑字（`::selection` 变色）、CSS 模糊遮挡（遮挡本身就是线索）、同色隐形链接、藏在图片里的文字 |
| G 文件矛盾推断 | 让文件互相矛盾：合规结论 vs. 标红条目、申报用途 vs. 行程终点、表彰文字 vs. 后来的身份、由同一日期互锁的页面。页面同时给出两组数字，把矛盾留给读者 |
| H 凭据组合登录 | 多字段校验（校区 + 姓名 + 部门 + 床位）、URL 白名单（假网页时光机只接受一个域名） |
| I 知识搜索教学 | 答错时提示"去网上搜一搜"——教会玩家使用站外搜索引擎（核心 ARG 技能） |
| J 情感 / 叙事谜题 | 心理问卷、分支对话；没有对错，只有选择；终局可以向玩家询问现实时间 |
| K 禁词触发 | 特定词触发整页恐怖转变（M6）；搜索框变成俄罗斯轮盘 |
| L 分阶段类型 | 解锁后的倒计时黑屏（"系统已经注意到你"）、打字机删除并重打、滚到底部的伪导航（"现在离开"）（M12） |
| M 元游戏彩蛋 | `ex` 页面收集（作者页揭示总数）、奖励 DOM 检查者的隐形链接、打破虚构 / 现实边界的外链（M11） |

**难度由文案暗示来调节。** 客户端谜题总可绕过；用哈希关键词表（阻止读源码通关）与不剧透的
文件名来缓解。产品是伪装，不是锁（R4）。

## 4. 文案规则（核心）

1. **表层：极度日常**——温暖、官僚或营销语域；日常感就是伪装。
2. **暗层：零形容词，冷文件**——一桩谋杀记录成台账（姓名 | 日期 | 备注：已由 X 确认）；一场悲剧记录成病历（主诉 / 病史 / 剂量）。恐怖来自公文语域。
3. **重复可视化执念**——一句话手抄 21 遍；67 遍祈文砌成一面墙；一个名字在交易记录里出现 10 次。
4. **黑话词表**：暗层有自己的术语（供奉 = 献祭，香客 = 猎物）；学会黑话本身就是隐藏的进度条。
5. **双说法对照**：同一事实两种写法，一层一种；玩家自己拼出真相。
6. **日常生活承载谜题**：密码素材必须先是一条真实的生活痕迹（孩子照片的发布日期 = 密码；一句"我的本命年" = 出生年推断）（R3）。
7. **缺席比在场更可怕**：停在"在吗，你还在吗？"的帖子；`[该内容已被删除]`；死人开关邮件。
8. **仿真噪声**：垃圾邮件、报错 JSON、`report_FINAL_v2_actually_final.pdf`、敷衍回复（"顶"）——无用信息堆出人味。
9. **失败消息是文案位置**：`密码错误 🎂` 提示来源并就此打住；光秃秃一句"错误"被禁止（R4）。
10. **一句箴言点题**：一副警句对联概括小说的因果逻辑，放在最深处。
11. **两种声音**：虚构内文本（页面、文件、通知、报错文案）为站点自身受众而写。引导文字（入口页、硬件需求）用朴素陈述句对玩家说话，不携带答案，也不写实现说明。
12. **中性表层页面**：不承载线索的页面照样写完整。员工名册列出每位员工及职务、任期、职责，包括关键人物；公开页上没有任何东西承认情节（R5）。
13. **文件格式就是现实感**：公告读起来像公告——发布主体、文件编号、日期、受文者、正文、署名与印章、分发范围。合同携带双方、条款、金额、日期、印章（R6）。
14. **陈述句**：文案把存在的东西说一遍。对偶句式（是…不是… / 是…而是… / 不能…只能… / 并非…而是…）与拟人读起来像议论文，稀释文件语域，且是可识别的机器写作痕迹。页面需要排除某物时，用自己的一句朴素话排除它。
    - 改前：这里没有随机密码，每一把钥匙都是某个人一生留下的痕迹。
    - 改后：每一个密码都出自站内某个人留下的生活痕迹：生肖、工号、纪念日。
