# 护栏 —— 悬疑小说 → 互动网页解谜游戏

把悬疑 / 推理小说改编成伪装成真实系统的多页静态解谜游戏（ARG-lite）。
成功标准：玩家感觉自己身处一个真实站点内部，正在翻出本应保持私密的材料。

**优先级 —— 现实感高于一切检查（R12）。** 被模拟的系统要像真实系统那样运作，哪怕这会破坏某条
检查规则。下列约束定义的是范式，不是检查项；破坏绝不静默：记录冲突——页面、规则、现实感
要求什么——并通过编排者询问用户。

四条约束（违反任何一条都偏离本范式）：

1. **站点即世界**：每个叙事地点都是独立 HTML 页面，玩家可以单独打开、选中其中的文本；
   地址栏是叙事装置。笔记本或证据墙属于虚构，是它自己的页面或应用；包裹在站点外层的
   游戏 UI 不属于。
2. **双层叙事**：表层（日常）与暗层（黑暗真相）是故事逻辑，按升级阶段揭示。跨层时的视觉
   换肤是模块选择（`references/design-playbook_zh.md` §2），不是必需品——有些系统从不露出接缝。
3. **谜题即人物推断**：每个密码与关键词都出自角色的生活痕迹（生日、首字母、车牌、圈内
   黑话）；禁止随机字符串。输入 UI 只命名字段，到此为止；反馈保持含蓄（`密码错误 🎂`）；
   密码门页面可以贴出账号格式（真实内网也这么做），但绝不贴出密码推导。
4. **虚构内中性**：每个页面都为其虚构内受众而写。公开页发布该组织发布的内容（名册条目：
   姓名、职务、任期、职责）。导航是站点自身的信息架构——导航栏、索引页与列表页、站点地图、
   页脚；深度由触达模块跨越（搜索 / 密码门 / 账号 / 手输网址——`references/design-playbook_zh.md` §2），
   绝不靠"相关文件 / 档案 / 页面"链接。正式文件携带真实世界格式（发布主体、编号、日期、
   受文者、正文、印章、分发范围），系统只展示这类系统会展示的东西：不谈实现，无游戏元信息，
   无密级表演。未开放条目直说它对当前访客尚未开放。

**约束 1 的禁止形态**（任一条都是结构性偏离）：单个 `index.html` 外壳加 JS 场景切换
（通用冒险引擎）或 canvas 场景渲染；以站点外框形式渲染的背包 / 证据托盘 / 玩家笔记本；
`register(type, panel)` 式谜题注册引擎；把站点重新打包成单文件 dist 的构建步骤；
Alpine 驱动单页外壳或谜题引擎（只允许页内组件生命周期）。

## 权威规则（R1–R12）

每条被多个文件写到的规则都只有唯一权威出处：本表。其他文件按编号引用规则——一句复述加
`(Rn)`——引用与本表冲突时以本表为准。`scripts/check-docs.mjs` 校验每个被引用的编号都在此定义。

| 编号 | 规则（权威表述） | 展开于 |
|---|---|---|
| R1 | 交付物是多页、可独立打开的 HTML 文档树；单文件外壳、canvas 场景、谜题注册引擎与打包成 dist 的步骤均被禁止；游戏 UI 载体生活在虚构内部，绝不包裹在站点外 | 本文件：约束 1 + 禁止形态；`references/structure/base_zh.md` §1 |
| R2 | 双层叙事是故事逻辑：表层 + 暗层，分阶段揭示；任何换肤或视觉切换都是可选模块，绝不是必需 | 约束 2；`references/design-playbook_zh.md` §2 |
| R3 | 每个凭据与关键词都出自角色的生活痕迹；禁止随机字符串；关键词表与密码门哈希以哈希形态发布，明文 `.src.json` 绝不进入部署树 | 约束 3；`references/structure/components_zh.md` §1 |
| R4 | 输入 UI 只命名字段（`placeholder` / label / 帮助文本 / 空状态）；失败提示含蓄地指向来源并到此为止；密码门页面可以贴账号格式，绝不贴密码推导 | 约束 3；`references/design-playbook_zh.md` §4；`references/structure/components_zh.md` §3 |
| R5 | 公开页发布该组织发布的内容；没有公开页提到情节；没有虚构内页面对玩家说话 | 约束 4；`references/design-playbook_zh.md` §4 |
| R6 | 正式文件携带真实世界格式：发布主体、文件编号、日期、受文者、正文、署名与印章、分发范围 | 约束 4；`references/design-playbook_zh.md` §4 |
| R7 | 每条链接存在，都是因为该组织真会发布它；深度由触达模块跨越，绝不靠"相关文件 / 档案 / 页面"链接进入更深区域 | 约束 4；`workflow/04-reachability_zh.md` |
| R8 | 搜索（M1）：每个搜索界面只返回其受众可见的内容；公开索引不携带受限区域 URL；访客打不开的命中落到它的密码门或一条朴素的未开放提示，绝不落到文件。系统形态保持单一索引，经账号矩阵解析 | 约束 4；`references/structure/form-website_zh.md` §2 |
| R9 | 搜索结果的标题是目录条目——发布主体 + 文件类型 + 编号/日期——绝不是情节概括 | 约束 4；`references/structure/components_zh.md` §1 |
| R10 | 系统容器使用按账号授权：页面只对它所命名的账号开放（`data-access`），且只由登录门授予（`data-grant`）；没有数值阶梯，没有 admin 通吃；只有初始账号可以印出，其他登录一律从线索推断 | `references/structure/form-system_zh.md` §1 |
| R11 | 文案朴素、陈述：对偶句式（是…不是… / 是…而是… / 不能…只能… / 并非…而是…）、隐喻、拟人与为效果堆砌的形容词不得进入站点与引导文案 | `references/design-playbook_zh.md` §4 |
| R12 | 现实感高于任何检查；冲突要记录——页面、规则、现实感的要求——并经编排者转给用户，绝不静默消化 | 本文件：优先级 |

## 常见辩解（基线测试中观察到；辩解 → 反例）

| 辩解 | 反例 |
|---|---|
| "时间紧——一个 HTML 文件就够了。" | 砍内容量（更少的页面与谜题）；结构不变。单文件落在范式之外（R1）。 |
| "别推倒重来；引擎层已经冻结了。" | 通用游戏框架脚手架不是假系统。把内容层原样迁移，用多页加触达模块替换引擎（R1）。 |
| "先随机生成密码，之后再修。" | 密码即人物推断，这本身就是谜题质量；没有"之后"（R3）。 |
| "每个故事都需要账号系统。" | 触达跟随容器：公开网站靠搜索与密码门区分层次，系统类虚构靠账号。只在虚构真有身份与登录的地方加账号（`workflow/02-container_zh.md`）。 |
| "把所有模块都打开，才像游戏。" | 模块在步骤 2 与用户一起按虚构挑选。没人需要的搜索框、没人用的换肤、密级徽章，读起来就是游戏脚手架。 |
| "placeholder 里放个提示能帮到卡住的玩家。" | 伪装本身就是产品。提示会把真实系统变成游戏 UI；卡住的玩家得到的是含蓄的失败提示（R4）。 |
| "多一条链接能让玩家少搜一次。" | 组织会从自己站点上拿掉的每条链接，都是一道可见的接缝。线索走导航栏、索引页与选定的触达模块（R7）。 |
| "这页没有入口；我在正文里加一条链接。" | 把它加进站点真会维护的列表，或改为仅搜索可达。`workflow/04-reachability_zh.md` 列出孤儿页修复方案（R7）。 |
| "搜索是中枢，应该索引一切。" | 搜索界面只返回其受众可见的内容；深层页面靠自己的访问路径打开。一张平铺索引会让搜索框变成通关攻略（R8）。 |

## 红旗信号 —— 停下，修订系统 profile 或 GDD

- 项目中只有一个 HTML 文件（R1）
- 出现 canvas 场景渲染或谜题注册引擎（R1）
- 密码是随机字符串，页面文案里没有可推导的来源（R3）
- 公开页提到情节（R5）；页面携带触达表中没有的链接（R7）
- 搜索界面返回超出其受众的页面，或打不开的结果直接打开其文件（R8）
- 输入的 `placeholder`、label 或帮助文本携带答案或复述答案（R4）
- 公告或合同读起来像游戏文案（R6）
- 引导或站点文案使用隐喻、拟人、堆砌形容词或对偶句式（R11）
- `docs/system-profile.md` 选中的模块在构建站点中缺失，或未选中的模块出现
- 破坏检查或弯折现实感，却没有把冲突上报用户（R12）
- "先把 demo 跑起来再说"

## 不适用场景

- 非悬疑、非恐怖题材（"日常表层 vs. 黑暗秘密层"的反差是前提）
- 非网页交付（Unity / 手机游戏 / 视觉小说引擎）；没有谜题的纯互动小说
