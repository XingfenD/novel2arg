# 步骤 8 — 自检

**输入：** 完成的站点加全部 `docs/` 产物。**输出：** 每项一行通过/失败判定，写入 `docs/self-check.md`。每一项都必须通过。本清单是权威版本——references/structure/tooling_zh.md 只覆盖检查节奏、共享 CONFIG 与人工方法；命令不在那里重复。

## 结构

- [ ] `find . -name "*.html" | wc -l` 返回 10 或更多。交付物是多 HTML 文件树（R1）。
- [ ] 检查器之前先干净地运行 `node tools/build-keywords.mjs`——过期的哈希表会掩盖链接与可解性漂移（R3）。
- [ ] `node tools/check-links.mjs` 报零死链（与零层泄漏）。
- [ ] `node tools/check-solvable.mjs` 报每个密码门已解锁、每个页面可触达，并以 0 退出。
- [ ] `node tools/check-credentials.mjs` 通过（每个派生凭据都由公开页部件拼装、绑定到其门、保持零明文）——只要 `data/credentials.src.json` 存在就运行。
- [ ] `node tools/check-reachability.mjs` 以 0 退出（演算副本：一旦每个凭据已知，每个门都解锁、每个页面都可触达）。
- [ ] `grep -rL "alpine.min.js" --include=*.html .` 无输出。
- [ ] `grep -rn "keywords.*src\|credentials.*src" --include=*.html .` 无输出（没有页面引用明文源表）。
- [ ] **模块匹配。** 构建出的站点与 `docs/system-profile.md` 一致：每个选中的模块都在且可用，每个未选中的都不在（没有死皮肤、搜索表、门组件或账号家具）。
- [ ] **资产清单已对账。** GDD 资产清单声明的每个资产都存在于 `assets/` 下，且至少被一个页面引用（`grep -rn "<asset-filename>" --include=*.html .` 至少 1 个命中）。没写出来的 `<img>` 没有 `src` 供 check-links 解析，所以这是针对 GDD 清单的人工对账（`references/structure/tooling_zh.md` §3 第 9 项）。
- [ ] 入口页与一个秘密页的控制台：零错误、零 404（包括每个 `<img>` 请求）。
- [ ] 定时器与观察者在 `destroy()` 中释放。

## 触达性（对构建树重跑 workflow/04）

- [ ] `node tools/check-solvable.mjs` 通过：它从入口页出发，沿顶栏搜索、正文链接与门后链接遍历图，报告门解锁与不可触达页面。它把下面三项自动化了；只有它无法建模的才人工做。
- [ ] 从 `index.html` 出发的图遍历到达每个页面。零孤儿。
- [ ] `pages/` 下的每个 `<a>` 都能追溯到触达表中的一条合法入站路径。人为植入的线索链接已清除。
- [ ] 两张明文关键词表中的每个键都逐字出现在同一受众的某个可触达页面的文案里。
- [ ] 公开关键词表不携带受限区域 URL（默认 `internal/`；`secretUrl` 配置项）。
- [ ] 访客可能打不开的每个结果或列表行都落到它的门或一条朴素的未开放提示；没有任何条目直接打开其文件。
- [ ] 系统容器（M3）：每个 `data-access` 账号都由某个登录门授予（`data-grant`）；没有页面能经权限阶梯或浅层页的"相关档案"链接到达；且指向受保护文件的搜索命中在指名账号认证之前保持不可触达。

## 谜题完整性（重跑 workflow/05 Q4）

- [ ] 对构建树的泄答扫描：任何门页面或推理链页面上都没有答案、复述、推导规则或位置字符串。扫描页面**外框**与表单 UI 一样重要——`<title>`、顶栏与页脚在实践中都泄露过答案。
- [ ] `grep -rn "placeholder=" --include=*.html .`——每个值都只命名其字段。
- [ ] `grep -rn "data-fail-hint\|gate-hint" --include=*.html .`——失败提示含蓄地指向来源（R4）。`密码错误 🎂` 通过；`想想陈师傅的本命年` 失败。
- [ ] `node tools/check-solvable.mjs` 把每个**逐字**凭据解析到先前页面的文案，并指明来源页。这替代人工溯源；仍要自己把流程完整走一遍，判断语气与节奏。
- [ ] `node tools/check-credentials.mjs` 把每个**派生 / 组合**凭据解析到其公开页部件，并断言零明文：任何页面上都不出现完整账号字符串（客户端遮蔽——`x-show`、CSS 类、元素级 `data-access`——在没有服务端鉴权的静态站点上不是隐私；HTML 会送达每个访客）。
- [ ] 没有任何一页同时安置同一凭据的两个部件（"零跳"通关）：如果工号与年份印在同一页，玩家无需推导直接照抄。按 GDD 谜题分配表拆开。
- [ ] 两张关键词表中的结果标题都是目录条目；没有一条概括文件内容。

## 一致性（GDD 实体登记表 vs. 构建树）

- [ ] 每个共享实体——人名、编号 / 车牌、账号、页面标题、导航标签、文件编号、关键日期——在 GDD 实体登记表与每个承载它的页面之间逐字节一致。名册漏掉一个出现在值班表上的人，或一个页面回应两个标题（导航 vs. 它自己的 `<title>` vs. 正文引用），在此失败。
- [ ] 每个示例都满足它所演示的规则。样例账号必须服从声明的推导规则（一套"拼音首字母"规则不能用全拼字符串作示例），且其形状与真实值一致（长度、分隔符、掩码）。
- [ ] 没有任何 GDD 自相矛盾存活进页面：某一行 GDD 禁止的值，不会被同一页面上另一行要求（登记表是仲裁者）。

## 虚构内中性

- [ ] 每个公开页都当作该组织的一份文件来读。它完整、可信、不泄露任何信息。没有页面提到情节。
- [ ] 每份公告、通知、合同与证书都带有发布主体、文件编号、日期、受文者、署名或印章。
- [ ] 没有任何虚构内页面直接对玩家说话。

## 文案语域

- [ ] 入口仪式页的引导文字是朴素的陈述句。
- [ ] 对偶句式（是…不是… / 是…而是… / 不能…只能…）不出现在站点文案中（R11）。用 `grep -rnE '不是|而是|不能.*只能|并非.*而是' pages/ index.html` 扫描。
- [ ] 引导文字与文件中没有为效果堆砌的隐喻、拟人或形容词。

## 呈现

- [ ] 长页面上页头固定在视口；正文在其下滚动。
- [ ] 核心交互在手机宽度可用。
- [ ] 浏览器全站巡检：在桌面与手机宽度加载**每个**页面（加每种搜索状态：命中 / 未命中 / 禁词）。收集控制台错误、`requestfailed`（包括每个 `<img>`）、横向溢出（`scrollWidth > innerWidth`），以及每个 `[x-data]` 元素是否真的初始化。部分抽检会漏掉缺陷——一个 CSS 优先级 bug 曾只在秘层静默禁用了两种声明过的谜题类型。
- [ ] **跨标签页会话（M3）。** 登录后打开一个搜索 / 结果链接（`target="_blank"`）：受保护文件在新标签页中也必须解锁。关闭浏览器再打开：已登出。按标签页的 `sessionStorage` 在第一步失败；会话 Cookie 通过。`check-solvable.mjs` 把身份建模为一个全局集合，看不到这一点——它两种情况下都报绿，因此这个人工测试是唯一的把关点（`references/structure/tooling_zh.md` §3 第 7 项）。
- [ ] 没有页面跨会话保存解锁状态或阅读进度，也没有页面向玩家解释其存储。`grep -rn "localStorage\|sessionStorage" --include=*.js --include=*.html .` 并确认除文档化的会话辅助函数外没有任何代码碰它。
- [ ] 感官谜题的硬件需求在入口页声明，且没有声明站点实际未实现的东西。
- [ ] 选择 M5 时：进入深层区域会重绘整个页面——背景、标题、徽标、页脚——且没有选择它的项目不触发主题切换。

本步骤的基线测试陷阱：`references/common-mistakes_zh.md` §8 —— 交回产物前逐条检查。
