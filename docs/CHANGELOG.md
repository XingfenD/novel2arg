## [Unreleased]

### Changed / 变更

- Parallelize the workflow wherever the inputs allow it: rounds 3b and 3c dispatch together (both read only `docs/gdd-plan.md`, and 3d already exists to settle their disagreements); steps 4 and 5 dispatch together as gates over disjoint GDD sections (5 drops its `docs/reachability.md` input — the orchestrator cross-checks the pages 4 cuts against 5's source-page column); step 6a dispatches the moment step 2 returns and runs beside steps 3–5 (its prompt was already plot-blind); large novels split at chapter boundaries into one subagent per chunk plus a merge round; and inside step 7 phase 4 splits into 4a (generate assets with phase 1 — they depend on the manifest alone) and 4b (wire after phase 3), with phase 5 beside phase 3. The serial spine — 1→2→3a→3d→review→6b→7.1→7.2→7.3 — and both human gates are unchanged.
- 在输入允许的范围内并行化工作流：3b 与 3c 同派（两者都只读 `docs/gdd-plan.md`，3d 本来就是为弥合分歧而存在）；步骤 4 与 5 作为双 gate 同派，各审互不相交的 GDD 小节（5 去掉 `docs/reachability.md` 输入——由 orchestrator 把 4 砍掉的页与 5 的来源页列对一次）；6a 在步骤 2 一返回即派发，与 3–5 并行（它的 prompt 本来就是 plot-blind）；大长篇按章节边界拆成每 chunk 一个 subagent 加一个合并轮；步骤 7 内阶段 4 拆为 4a（随阶段 1 生成资产——资产只依赖 manifest）与 4b（阶段 3 后接线），阶段 5 与阶段 3 并行。串行主干——1→2→3a→3d→review→6b→7.1→7.2→7.3——与两处人工 gate 不变。

- Rewrite step 3's rounds as explicit read→write sequences: after every read the next tool call is the write that read unblocks — never a second content read, never a planning pass in between. Reading everything before writing anything is the protocol that scheduled the mega-think, and three real runs truncated inside it. Round 3a now extracts the whole GDD as one-line rows into `docs/gdd-plan.md` under ten fixed headings (the GDD's own numbering), so rounds 3b and 3c read that file block by block instead of re-deriving from the deconstruction; runtime artifacts are read by named table or heading, never whole. The dispatch contract gains two clauses: a prompt carries paths and the round definition only — no inline digest of an artifact the round will read anyway — and the step file's reading list is complete, with nothing added at dispatch time.
- 把步骤 3 各轮改写为显式的 read→write 序列：每次 read 之后的下一个工具调用就是它解锁的那次写——不允许第二次内容读取、不允许中间的规划 pass。“先读完全部再动笔”正是把 mega-think 安排到最后的协议，三次真实运行都截断在其中。3a 现在把整个 GDD 以一行一行的形式抽进 `docs/gdd-plan.md`，挂在十个固定标题下（沿用 GDD 自身编号），3b/3c 因此按块读该文件、不必再从解构文档重新推导；运行时产物按具名表格或标题读取，不再整文件读。dispatch 契约新增两条：prompt 只带路径与轮次定义——不得内联该轮反正要读的 artifact 摘要；步骤文件的必读清单即完整清单，派发时不得增补。

- Split step 3 into four subagent rounds — 3a writes `docs/gdd-plan.md` (page map, entity list, access inventory, puzzle allocation), 3b writes `docs/gdd.md`, 3c writes `docs/registry.md` from the plan's entity list, 3d reconciles the registry against the GDD — after a real project's step-3 turn exhausted its response budget three times over: enumerating a 44-page map inside one think block, digesting the reference stack before a single row was written, and replaying two large files for one whole-document consistency scan. Every round now follows two writing rules — the file is the only digest (no restating inputs in reasoning) and write incrementally (the first tool call after the last read creates the file, later calls append 5–10 rows or one section) — round outputs travel as named files, never pasted into the next prompt, and the scan is a fixed-order per-section diff that fixes as it reads. Reads are section-scoped — a cited `file.md §N` is its own read call (that section's lines, not the whole file), so no think ever holds two references at once — and each round's Output section names its first tool call, because a general rule at the top of the file drifts out of attention by the time a 40-page round reaches it.
- 把步骤 3 拆成四个子代理轮次——3a 写 `docs/gdd-plan.md`（页面地图、实体清单、访问清单、谜题分配），3b 写 `docs/gdd.md`，3c 从计划实体清单写 `docs/registry.md`，3d 对账登记表与 GDD——此前真实项目的步骤 3 三次耗尽响应预算：在单个 think 块里枚举 44 页地图；消化参考件到一行未写；为一次全文一致性扫描回放两个大文件。现在每轮遵守两条写作规则——文件即唯一 digest（禁止在推理中复述输入）与增量落笔（最后一条 read 之后的第一个工具调用即建文件，后续每次追加 5–10 行或一节）——轮次产物以指名文件传递、不粘贴进下一个 prompt，扫描改为固定顺序的逐节 diff、边读边修。读取按小节限定——引用的 `file.md §N` 是独立的 read 调用（只读该节、不读整份），任何 think 都不会同时握住两份参考；每轮 Output 段写明首个工具调用——总则放在文件开头，等一轮走到 40 页的深处时已挤到注意力边缘。
